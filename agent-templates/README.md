# Шаблоны инженерных агентов

Это каталог заготовок, а не активная команда и не архитектура runtime-агента продукта. Используйте [базу задачи](../docs/agent-base/README.md) и существующий [template_lite](../template_lite/README.md).

| Заготовка | Как применять |
| --- | --- |
| [Профиль](../template_lite/agent-profile.md) | После достаточного контекста заполнить и сохранить в `skils/<feature>-<domain-role>.md` |
| [Задание](../template_lite/task-assignment.md) | Перед dispatch заполнить в `handoffs/<task-id>/assignment.md` конкретной feature |
| [Поведение](../template_lite/agent-behavior.md) | Применять вместе с профилем, заданием и инструкциями проекта |
| [Ограничения](../template_lite/constraints.md) | Выбирать только применимые правила согласованных технологий |

Команда выбирается по реальным границам ответственности. Методы берутся из `role-skills/` плагина; порядок и prerequisites — из `phases/`. До назначения не создавайте профили, `skils/` или будущий постоянный roster.

Перед запуском профиль должен содержать доменный результат, триггер, входы, разрешённые действия и файлы, выходы, DoD, проверку, escalation и условия независимости. Каждое задание получает одного владельца; параллельные задания не пишут в одни файлы. Design/plan/final review поручаются отдельному проверяющему. Если независимый запуск недоступен, фиксируется ограничение отдельного прохода, а не независимое ревью.

Handoff: `assignment.md` → `result.md` с фактическими доказательствами → `todo.md` с остатками. Общие workflow/status/routing/decisions обновляет оркестратор. Dispatch возможен только после применимых gates; наличие шаблона не разрешает внешние действия.
