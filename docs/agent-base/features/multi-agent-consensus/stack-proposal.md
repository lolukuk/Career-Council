## Рекомендуемый вариант

Python в существующей папке `council` (на машине доступен Python 3.13); LangGraph для явного workflow со структурированным состоянием; Pydantic для контрактов позиций, решений и голосов; pytest для запрошенных сценарных проверок. Совместимость и точные версии зависимостей проверяются после утверждения, в отдельном окружении.

LangGraph предложен потому, что присутствует в исходном задании и позволяет совместить модельные шаги с детерминированными переходами, состоянием и циклом пересмотра. Это соответствует приоритету протокола. Его возможности подтверждены [официальной документацией](https://docs.langchain.com/oss/python/langgraph/overview) и [Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api). LangGraph не является условием корректного консенсуса: инварианты всё равно проверяются прикладным кодом.

Hybrid retrieval: BM25 в локальном коде плюс настоящие dense embeddings через Sentence Transformers; объединение результатов и правила охвата уточняются в дизайне. [Sentence Transformers](https://sbert.net/docs/sentence_transformer/usage/usage.html) предоставляет семантические векторные представления текста. Модель embeddings выбирается под язык досье, без отдельного vector DB. Hash-векторы или ручные синонимы не выдаются за семантический поиск.

LLM-провайдер, модель и SDK пока unknown. Интерфейс модели должен позволять сценарные ответы и реальный вызов без изменения протокола. Для live-демонстрации потребуется доступная конфигурация; ключи в документах, логах и исходниках не сохраняются. Желание локального задания использовать mini-модели учитывается как предложение, но не фиксирует текущую модель или тариф.

Формат прототипа: CLI, локальные JSON-артефакты состояния/трассы и Markdown-отчёт; один процесс. Это не выбор БД и не обещание crash recovery. Web UI, LangSmith, очереди, серверная платформа и deployment для этого объёма не нужны.

## Альтернатива

Python и собственная конечная машина состояний вместо LangGraph: меньше framework-зависимостей и тот же контракт консенсуса, но больше собственной логики маршрутизации и расхождение с FR-8 локального задания. Остальные контракты и проверки остаются нужны.

Рекомендация на согласование: Python + LangGraph + Pydantic + BM25/Sentence Transformers + pytest; провайдер LLM выбирается по доступу пользователя. После утверждения требований и стека следующий шаг — точный дизайн, независимая проверка и отдельное согласование дизайна. Реализация до этого не начинается.
